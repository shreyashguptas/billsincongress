# Bills.Congress

**An independent, open-source record of every bill in the U.S. Congress — sourced directly from the official Congress.gov API and presented the way a newspaper of record would.**

Live at **[billsincongress.com](https://billsincongress.com)**.

![Bills.Congress homepage — the 119th Congress at a glance](public/readme/preview.png)

---

## What is this?

Congress.gov already publishes everything you need to follow legislation — but it's built for legislative staff, not citizens. Titles are jargon. Status codes are cryptic. You have to know exactly what you're looking for before you can find it.

Bills.Congress takes the same primary data and presents it clearly:

- **Browse every bill** in the current Congress and the two before it, filtered by chamber, status, policy area, sponsor, or state.
- **See a bill's journey** through Congress on a visual progress timeline — from introduced, to committee, to passing one chamber, to becoming law.
- **Read a plain-English summary** of any bill, generated by an AI model from the official text.
- **Ask questions** about any bill in a chat panel — multi-turn, with the bill's full context loaded automatically. No legal background needed.
- **Explore an interactive dashboard** of Congress activity — totals, status breakdowns, top sponsors, and policy-area trends.
- **Learn how Congress works** in a short, plain-English primer covering the two chambers, what a bill is, and the journey to law.

It's mobile-friendly, works in light or dark mode, and you don't need an account to read anything.

## Where the data comes from

Every bill, sponsor, action, and status on this site comes from the **[official Congress.gov API](https://api.congress.gov/)** — a public service of the Library of Congress.

| Detail            | Value                                                     |
| ----------------- | --------------------------------------------------------- |
| Source            | Congress.gov API                                          |
| Update cadence    | Daily incremental sync, weekly full refresh               |
| Coverage          | The current Congress and the two before it (e.g. 117–119) |
| Affiliation       | Independent — not affiliated with the U.S. government     |
| Source data       | Public domain                                             |
| License           | [MIT](./LICENSE)                                          |

When you load a bill page, the timestamp at the top tells you exactly when its data was last refreshed.

### Tech stack

| Layer        | What we use                                                              |
| ------------ | ------------------------------------------------------------------------ |
| Frontend     | Next.js 16 (App Router), React 19, TypeScript                            |
| Styling      | Tailwind CSS, shadcn/ui (Radix primitives), Framer Motion                |
| Backend      | Convex (database, queries, mutations, actions, scheduled jobs)           |
| Auth         | `@convex-dev/auth` with email OTP via Resend, plus Google OAuth          |
| Rate limits  | `@convex-dev/rate-limiter` — 5 chat messages/day anon, 100/day signed-in |
| AI chat      | OpenRouter (model set per deployment), history persisted in Convex       |
| Hosting      | Cloudflare Workers via OpenNext (frontend) + Convex Cloud (backend)       |

### Architecture at a glance

```
Congress.gov API
       ↓  (scheduled jobs in convex/crons.ts)
Convex actions (convex/congressApi.ts, convex/sync.ts)
       ↓
Convex mutations (convex/mutations.ts) → Convex DB (convex/schema.ts)
       ↓
Convex queries (convex/bills.ts) + AI actions (convex/llm.ts)
       ↓
Next.js App Router (app/) — server components fetch via convex/nextjs,
                            client components subscribe via convex/react
```

Heavy analytics aren't computed on every page load. They're **precomputed nightly** into dedicated tables (`congressStats`, `congressPolicyAreas`, `congressSponsors`) so the dashboard reads single rows instead of scanning the whole `bills` table. Full details: [`Documentation/interactive-dashboard.md`](./Documentation/interactive-dashboard.md).

### Running it locally

You'll need Node.js 20+ (Node 24 LTS is the recommended runtime) and a package manager (`npm`, `pnpm`, or `bun` — examples below use `npm`).

```bash
git clone https://github.com/shreyashguptas/billsincongress.git
cd billsincongress
npm install
```

Create `.env.local` with at least:

```env
# Convex — this repo points the local frontend at the production deployment
# (see "Production-only Convex" below for why)
CONVEX_DEPLOYMENT=prod:industrious-llama-331
NEXT_PUBLIC_CONVEX_URL=https://industrious-llama-331.convex.cloud

# Required for sync to pull bill data
CONGRESS_API_KEY=        # https://api.congress.gov/sign-up/

# Required for the AI chat panel (set on the Convex deployment, not in .env.local)
OPENROUTER_API_KEY=      # https://openrouter.ai/keys
OPENROUTER_MODEL=        # optional override, default deepseek/deepseek-v4-flash-0731
OPENROUTER_PROVIDERS=    # optional override, default deepinfra,amazon-bedrock (US, zero-retention)
OPENROUTER_FALLBACK_MODELS= # optional; blank DISABLES failover. Default:
                         #   deepseek/deepseek-v4-flash,amazon/nova-lite-v1

# Optional
NEXT_PUBLIC_ANALYTICS_ID=
```

Then start the dev server:

```bash
npm run dev
```

Open <http://localhost:3000>.

#### Production-only Convex

This project deliberately does **not** use `npx convex dev`. Local development reads and writes against the production Convex deployment, which avoids maintaining a duplicate copy of ~38k bills and the cost of a second sync schedule. Treat the database as production data — never run destructive mutations against it without coordination.

To deploy Convex function changes:

```bash
npx convex deploy
```

### How the sync works

Four scheduled jobs (defined in `convex/crons.ts`) keep the database in step with Congress.gov:

| Job                        | Schedule          | Purpose                                |
| -------------------------- | ----------------- | -------------------------------------- |
| `daily-incremental-sync`   | Daily 1 AM UTC    | Pull bills changed since last run      |
| `weekly-full-sync`         | Sunday 2 AM UTC   | Full refresh of all tracked Congresses |
| `weekly-repair-incomplete` | Wednesday 3 AM UTC| Backfill bills missing details         |
| `daily-recompute-stats`    | Daily 4 AM UTC    | Rebuild precomputed analytics tables   |

The sync only covers the **current Congress and the two before it**. As of 2026 that's Congresses 117, 118, and 119.

You can manually trigger a stats recompute or wipe a Congress (rarely needed) with:

```bash
npx convex run --prod congressApi:triggerRecomputeStats '{}'
npx convex run --prod congressApi:deleteCongress '{"congress": 108}'
```

### Bill progress stages

Every bill has a numeric `progressStage` mapped to a label:

| Stage | Label                |
| ----- | -------------------- |
| 20    | Introduced           |
| 40    | In Committee         |
| 60    | Passed One Chamber   |
| 80    | Passed Both Chambers |
| 85    | Vetoed               |
| 90    | To President         |
| 95    | Signed by President  |
| 100   | Became Law           |

### Performance rules (please read before writing queries)

Convex queries are billed per row scanned. Two rules keep this site fast and cheap:

1. **Always use indexes.** `ctx.db.query("bills").collect()` will time out on the production dataset.
2. **Use precomputed tables for analytics.** If a number can be aggregated overnight, aggregate it overnight — don't recompute it on every page load.

See [`Documentation/interactive-dashboard.md`](./Documentation/interactive-dashboard.md) for the worked example.
